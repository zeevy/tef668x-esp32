The screens

Why this face

  • Condensed
    A 320px wide screen has to hold six digits of frequency at 62px. A condensed face fits them without shrinking them. Barlow Condensed is open licensed and converts cleanly with the LVGL font tool.
  • Tabular figures
    Not optional. With proportional digits the frequency jitters sideways every time a digit changes, and on a tuning display that is the one thing you cannot have.
  • Weight, not size
    Labels and values are separated by weight and colour, not by making labels smaller. Today both are 14px in the same colour, which is why the screen reads flat.
  • Subset it
    The 62px frequency font needs eleven glyphs: ten digits and a point. Subsetting takes it from about 180KB to under 20KB. The whole scale lands around 100KB, against 8MB of flash.

The menu trade, stated plainly. Going from 20px rows to 36px rows means five rows on screen instead of ten. That is a real loss and it is deliberate. LVGL scrolls, so nothing becomes unreachable, and a row you can read at arm's length beats two you have to squint at.

How it is built

Five layers, one rule: the core must not know a screen exists.

board/     One header per board. Pin map, feature flags.
           board_ats125.h, and the next radio is another header.

drivers/   tef668x, display, touch, encoder, keypad, rtc, battery.
           Each behind an interface. No globals.

core/      Tuner state machine, RDS decoder, band plan, memory
           channels, settings, volume AGC.
           No hardware. No UI. Builds and runs on a laptop.

ui/        LVGL screens, menus, panels. Talks to core through an
           API. Never touches a driver.

net/       Wi-Fi, web server, OTA, NTP, telemetry.

Two FreeRTOS tasks. The radio owns core 0 and the 43 ms RDS cadence. UI and network own core 1. They pass a state snapshot and a command queue, never a shared variable. That is why a slow web request cannot drop RDS groups, which in the current firmware it can.

Build order

Audio early, polish late. No phase starts before the one before it is green in CI.

  1. Phase 0
    Escape the cable
    Partition table, Wi-Fi with access point fallback, over the air update, rollback armed. Flashed once over USB. The last time the boot button is ever needed.
  2. Phase 1
    Foundations
    Layer skeleton, board header, one environment per board plus native, and CI with a coverage gate. One passing test before anything depends on the test path.
  3. Phase 2
    It is a radio
    Tuner driver, patch load, capability detection, band plan, encoder and keypad. Plain text on screen. Done when it tunes a station and plays audio.
  4. Phase 3
    Core logic, tested on a PC
    RDS decoder, settings, memory channels, volume AGC. All of it under test with no hardware attached. This is the phase that justifies the architecture.
  5. Phase 4
    The interface
    LVGL, fonts, the panel set, per band layouts, menu, boot screen, recovery screen. The largest phase.
  6. Phase 5
    Web and telemetry
    Web server, access PIN, settings pages, memory editor, telemetry over UDP and websocket, diagnostics, backup and restore.
  7. Phase 6
    The rest
    Spectrum view, sleep timer, alarm, power management, and over the air updates straight from a GitHub release.

The decisions that matter most

  • LVGL
    Today every menu row is written twice, once for the encoder and once for touch. LVGL treats them as two input devices on one UI, so touch becomes a setting rather than a second codebase.
  • Settings struct
    One versioned struct in NVS, not hand written byte offsets. Adding a setting is adding a field. The web UI then comes almost free, because the struct serialises straight to JSON.
  • Named strings
    UI code says STR_VOLUME_AGC, never an index. Inserting a string can never shift another one. English ships, the mechanism for more stays.
  • Telemetry
    The radio broadcasts its live state as JSON. No debug builds, no cable. Captures become test fixtures, which is how the RDS decoder gets tested against real broadcasts rather than invented data.
  • Measured
    No threshold is guessed and no power saving is claimed until it has been measured. A guessed signal threshold made the volume AGC do nothing for a week, and it failed silently.
  • Recovery
    One screen reached by holding the rotary button, rendered with safe display settings so it works when the broken setting is the display. Not seven button combinations nobody remembers.

Where these mockups are not the truth

The dimensions are real, the palette is real, and the type scale is the one being proposed. But this is SVG in a browser rendering Barlow Condensed as a web font. On the radio it will be the same family converted to LVGL bitmaps at each fixed size, so hinting and spacing will differ slightly.

The meter bars are drawn here as smooth gradients. On the panel they are discrete two pixel segments with the ramp computed in HSV, so the real thing steps rather than glides.

Everything on these screens is example data. The station, the frequencies and the readings are plausible values, not a capture from the radio.
